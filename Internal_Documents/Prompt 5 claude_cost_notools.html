Claude Code setup: .claude folder structure + prompt caching (no maxTurns, no tools variant)

Set up this repository's .claude/ folder structure and make sure prompt caching is on.

Scope: only .claude/, .gitignore, and CLAUDE.md (create it only if it is missing). Do not change application code, MCP servers, or permissions. Do not commit. Detect the OS and use the matching shell commands.

Phase 0: Preconditions

  1. Run claude --version. promptCacheTtl needs v2.1.242 or later, and omitClaudeMd needs v2.1.271 or later. If the version is older, report it and skip only those fields.
  2. Find a working Python command: try python, python3, then py -3. Record the first one that works as PYTHON.
  3. Back up .claude/, and CLAUDE.md if it exists, to .claude.bak-<YYYYMMDD-HHMM>/.
  4. List every existing file under .claude/. Leave files that are not in this spec unchanged, and record their names. Replace spec files that differ (the backup keeps the old version).

Phase 1: Prompt caching check and enable

Caching is on by default. It is disabled only by these environment variables, set to any value:
DISABLE_PROMPT_CACHING, DISABLE_PROMPT_CACHING_HAIKU, DISABLE_PROMPT_CACHING_SONNET, DISABLE_PROMPT_CACHING_OPUS, DISABLE_PROMPT_CACHING_FABLE.

  1. Search for these variables in every place they can come from. For each hit, record the source, line and value.
    • Project settings: .claude/settings.json, .claude/settings.local.json
    • User settings: ~/.claude/settings.json, ~/.claude/settings.local.json
    • Managed settings, read only:
      • Windows: C:\Program Files\ClaudeCode\managed-settings.json
      • macOS: /Library/Application Support/ClaudeCode/managed-settings.json
      • Linux: /etc/claude-code/managed-settings.json
    • The current process environment
    • Persistent environment:
      • Windows: User and Machine scope
      • macOS/Linux: shell profiles (~/.bashrc, ~/.zshrc, ~/.profile, etc.)
    • VS Code user settings and .vscode/settings.json
  2. Also record these, but do not change them. They override the cache settings:
    • FORCE_PROMPT_CACHING_5M
    • CLAUDE_CODE_PROMPT_CACHE_TTL
    • CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL
    • ANTHROPIC_BASE_URL
  3. Live check: open the newest .jsonl under ~/.claude/projects/ for this project. Report cache_read_input_tokens and cache_creation_input_tokens from the last few assistant messages.
  4. Give a verdict: ENABLED or DISABLED. If DISABLED:
    • Remove each disabling key from the project, user and editor settings and from shell profile lines. Keep every other key and line unchanged.
    • Remove User-scope Windows variables with [Environment]::SetEnvironmentVariable('<NAME>', $null, 'User').
    • Do NOT change Machine-scope variables or managed settings. Report them for an admin or IT to handle.
  5. If ANTHROPIC_BASE_URL points to a gateway, warn that the gateway must forward cache_control markers and the anthropic-beta header unchanged.

Phase 2: Check the model pins

Probe each pinned model once, in the shell:

claude -p "Reply with OK" --model <id> --output-format json

Probe the values of model, ANTHROPIC_DEFAULT_OPUS_MODEL, ANTHROPIC_DEFAULT_SONNET_MODEL and ANTHROPIC_DEFAULT_HAIKU_MODEL in .claude/settings.json.

  • If all of them answer: change nothing.
  • If one fails with "not available on your ... deployment": probe the model ID that the error suggests. If that ID answers, use it in Phase 3 and report old → new. If it doesn't, stop and report which model the cloud admin must enable.
  • Do not invent model IDs.

Validate:

  1. python -m json.tool .claude/settings.json must succeed.
  2. Diff the merged file against the backup. Every original line must still be present, apart from model pins replaced in Phase 2. Show the diff in the report.

Phase 4: Agent guard script

Create .claude/hooks/agent_guard.py with exactly this content. It logs every agent that Claude spawns. It also blocks an opus/fable model override on any agent other than the three Opus agents. If its input is unreadable, it does nothing.

"""PreToolUse guard for the Agent tool: logs every spawn and blocks expensive
model overrides outside the agents allowed to use them. Fails open on bad input."""
import datetime, json, os, sys

ALLOW_EXPENSIVE = {"architect", "planner", "opus-consultant"}
EXPENSIVE = ("opus", "fable")

raw = sys.stdin.read()
try:
    event = json.loads(raw)
except ValueError:
    sys.exit(0)

tool_input = event.get("tool_input") or {}
agent = str(tool_input.get("subagent_type") or tool_input.get("agent_type") or "").strip()
model = str(tool_input.get("model") or "").strip().lower()
blocked = bool(model) and any(m in model for m in EXPENSIVE) and agent not in ALLOW_EXPENSIVE

root = os.environ.get("CLAUDE_PROJECT_DIR") or event.get("cwd") or "."
try:
    with open(os.path.join(root, ".claude", "agent-calls.jsonl"), "a", encoding="utf-8") as log:
        log.write(json.dumps({
            "ts": datetime.datetime.now().isoformat(timespec="seconds"),
            "session": event.get("session_id"),
            "agent": agent or None,
            "model": model or None,
            "blocked": blocked,
            "tool_input_keys": sorted(tool_input.keys()),
            "description": tool_input.get("description"),
        }) + "\n")
except OSError:
    pass

if blocked:
    print(json.dumps({"hookSpecificOutput": {
        "hookEventName": "PreToolUse",
        "permissionDecision": "deny",
        "permissionDecisionReason": (
            f"Model '{model}' is reserved for {', '.join(sorted(ALLOW_EXPENSIVE))}. "
            f"Run '{agent or 'this agent'}' without a model override, "
            "or use /consult-opus for a design question."),
    }}))
sys.exit(0)

Do not change any other file in .claude/hooks/.

5a. Agents (.claude/agents/)

Use the aliases opus, sonnet and haiku, not model IDs; settings.json maps them to IDs.
Do NOT set maxTurns or tools on any agent. This variant tests agents without a turn cap and without a tool list, so every agent inherits all tools from the main session, including Agent. If an existing agent file has maxTurns or tools, remove that line only and report it (file and old value).

File model effort extra
architect.md opus high
planner.md opus high
opus-consultant.md opus high
implementer.md sonnet medium
test-engineer.md sonnet medium
code-reviewer.md sonnet high
log-triage.md haiku low omitClaudeMd: true
Explore.md haiku low omitClaudeMd: true

Descriptions:

  • architect: "Architecture decisions and ADRs for complex changes. Writes ADRs to docs/adr/. Use when a design choice needs recording."
  • planner: "Writes implementation plans to docs/plans/ listing every affected file and the tests to write. Use proactively before any change touching more than one file."
  • opus-consultant: "Answers one narrow design question in 300 words or fewer. Never edits files. Use only via /consult-opus."
  • implementer: "Implements code changes from an approved plan in docs/plans/. Touches only the files the plan lists. Use proactively for code changes."
  • test-engineer: "Writes and runs targeted tests named in the plan or the request. Use proactively for test work."
  • code-reviewer: "Reviews the current uncommitted diff and ranks findings as blocker, major or minor with file:line. Use proactively after code changes."
  • log-triage: "Digests long build, test or command logs into the failing items with file:line. Use proactively for any log over 200 lines."
  • Explore: "Read-only search and mapping of unfamiliar code. Returns paths and line numbers, one line each."

Every agent body ends with these lines, in this exact wording:
"Report every changed file, every open issue and every failing test in full. Do not shorten those lists. Keep everything else brief.
Stop as soon as the task is done. Do not start work the task did not ask for.
If a design question blocks you, stop and return the question in one sentence instead of guessing."

Additional body rules:

  • implementer, test-engineer: work only from the approved plan in docs/plans/ (or the files named in the request). Write the named tests first. Run only the targeted tests unless the plan says otherwise.
  • code-reviewer: review git diff only. Skip generated files, lockfiles and snapshots.
  • architect, planner: write only under docs/adr/ or docs/plans/. Never edit source code.
  • opus-consultant: answer the single question asked, in 300 words or fewer. No edits.
  • log-triage, Explore: output a list, one finding per line, no prose.

5b. Skills (.claude/skills/<name>/SKILL.md)

Do not set model or effort on any inline skill. On an inline skill, either one makes that turn re-read the whole conversation uncached.

Skill Frontmatter
plan context: fork, agent: planner, background: false
implement context: fork, agent: implementer, background: false
test context: fork, agent: test-engineer, background: false
review context: fork, agent: code-reviewer, background: false
consult-opus context: fork, agent: opus-consultant, background: false, disable-model-invocation: true
cost-report context: fork, agent: general-purpose, model: haiku, background: false, disable-model-invocation: true, allowed-tools: Read, Grep, Glob, Bash
wait inline, no model, no effort, disable-model-invocation: true

Each skill has a one-line description and an argument-hint. A forked skill doesn't see the conversation, so its body must stand alone and pass $ARGUMENTS through.

  • plan / implement / test / review / consult-opus: one short paragraph telling the agent its task is $ARGUMENTS and what to return.
  • cost-report:
    • If scripts/claude_usage/report.py exists, run it and summarise its output. Otherwise, read the session transcript and its subagents/ folder under ~/.claude/projects/<project>/.
    • In both cases, then read .claude/agent-calls.jsonl and list, per agent type: spawn count, models requested, blocked calls, and the description of every general-purpose spawn.
    • Mention that /usage shows the main session's totals for free.
  • wait: "Do nothing until the background task named in $ARGUMENTS reports back. Then summarise its result in 3 lines or fewer."
